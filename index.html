Ch4 · rejection sampling
01 · the decision

Should every task in a bundle carpool on one serverless environment?

the customer problem

A data engineer ships a bundle with eight notebook and Python tasks. Each one spins up and resolves its own environment, so a 6-minute job spends a big slice of its time installing the same packages over and over.

📌 pinned to: pain

the proposed change

Make sharing the default: tasks in a bundle join a shared serverless environment defined once in the bundle-root pyproject.toml, with a cap of k tasks per shared environment and a pre-flight dependency check at deploy time.

📌 pinned to: the bet

success metric

Environment setup minutes per job run, down at least 30% versus one environment per task.

📌 pinned to: north star

guardrails

Runs with a dependency conflict≤ 2.0%
P90 setup delay vs. isolatedno worse
Tasks re-run per 100 runs≤ 8
Hard failures (need a human)≤ 0.3%
📌 pinned to: do no harm

stakeholders

  • Bundles + CLI engineering (config, validate)
  • Serverless compute (pool sizing, isolation)
  • Lakeflow Jobs PM (task semantics, retries)
  • Support + solutions architects (conflict tickets)
  • Customer FinOps admins (setup spend)
📌 pinned to: who signs off

why it's hard

Sharing saves setup time, but every extra task adds pairs of dependencies that can clash. Pairs grow like k(k−1)/2, so risk climbs much faster than savings do.

📌 pinned to: tension
02 · live simulation room

The power of repetition: 2,000 job runs

Setup times come from a lumpy curve (fast cached resolves plus slow cold installs). There's no off-the-shelf sampler for that exact shape, so I draw from it by rejection sampling: throw proposals under an exponential envelope and keep the ones that land under the curve. Then I replay every run with shared environments of size k.

k = 1 means today's behavior: every task isolated.
Chance two tasks' dependencies clash (per pair).

04 · the math, from my Monte Carlo course

Rejection sampling, in plain words

1 · the shape

Telemetry gives me a curve f(s) for setup seconds, but not a formula I can invert. I can evaluate its height anywhere. That's all rejection sampling needs.

2 · the envelope

Pick an easy distribution g I can sample (an exponential, via −μ·ln U) and a constant M so that M·g(s) sits above f(s) everywhere.

3 · the coin flip

Draw s from g and U from Uniform(0,1). Keep s if U ≤ f(s) / (M·g(s)). The kept draws follow f exactly, because each spot survives in proportion to f's height.

4 · the price

On average only 1 in M proposals is kept, so the acceptance rate is 1/M. A sloppy envelope wastes compute, just like an over-provisioned cluster.

product example

The same trick turns any fitted latency or cost curve into a simulator: sample from the curve, push draws through the product's rules, and read off P90s, savings and risk before a single customer sees the change.

-- 1. Fit the setup-time curve from job telemetry (illustrative table names)
SELECT task_type,
       percentile_approx(env_setup_ms / 1000.0, array(0.5, 0.9, 0.99)) AS setup_s_p50_p90_p99,
       avg(CASE WHEN cache_hit THEN 0 ELSE 1 END)                     AS cold_install_share,
       count(*)                                                       AS n_tasks
FROM   main.apm_lab.job_task_env_events
WHERE  event_date >= current_date() - INTERVAL 28 DAYS
GROUP  BY task_type;

-- 2. Pairwise conflict rate from bundles that already share an environment
SELECT avg(CAST(had_resolver_conflict AS INT)) / avg(n_task_pairs) AS p_conflict_per_pair
FROM   main.apm_lab.shared_env_runs;
# 3. Rejection-sample the fitted curve and replay share sizes
import numpy as np
rng = np.random.default_rng(102)

def f(s, w=0.30):                      # fitted mixture shape (seconds)
    fast = s * np.exp(-s/18) / 18**2
    cold = s**3 * np.exp(-s/30) / (6 * 30**4)
    return (1-w)*fast + w*cold

mu = 70.0
grid = np.linspace(0.01, 600, 6000)
M = 1.01 * np.max(f(grid) / (np.exp(-grid/mu)/mu))

def draw(n):
    out = []
    while len(out) < n:
        s = rng.exponential(mu, n)
        u = rng.uniform(size=n)
        out.extend(s[u <= f(s) / (M*np.exp(-s/mu)/mu)])
    return np.array(out[:n])

print("acceptance ≈", 1/M)

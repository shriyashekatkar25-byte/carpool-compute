Should every task in a bundle share one serverless environment?

Mirrors Shared Serverless for Asset Bundles (Beta, Oct 22 2026).

Shriya Shekatkar · UCLA · Stats 102C Monte Carlo Methods

1. The decision

Customer problemA data engineer's 8-task bundle sets up its environment 8 times, re-installing the same packages before any work runs.
Proposed changeShare one serverless environment across tasks by default, capped at k tasks per environment, with a dependency check at deploy time.
Success metricEnvironment setup minutes per job run, down at least 30% versus one environment per task.
StakeholdersBundles/CLI engineering, serverless compute, Jobs PM, support, customer FinOps admins.

Guardrails

Runs that hit a dependency conflict≤ 2%
P90 setup delay vs. isolated environmentsno worse
Tasks re-run per 100 runs≤ 8
Hard failures needing a human≤ 0.3%

The tension: sharing saves setup time, but conflicts scale with pairs of tasks, k(k−1)/2, so risk grows faster than savings.

2. Simulation

2,000 simulated job runs. Setup times are drawn from a fitted curve using rejection sampling, then each run is replayed at every cap k.

k = 1 is today: every task isolated.

X axis: cap k. Blue: setup minutes saved. Black: share of runs with a conflict (2% limit dashed). Dot marks the largest k that clears every guardrail.

How the setup times are drawn: proposals under the dashed envelope; blue dots land under the target curve and are kept, grey dots are rejected.

3. Director memo

4. The method: rejection sampling

  1. Telemetry gives a curve f(s) for setup seconds. I can compute its height, but there's no simple formula to sample it directly.
  2. Pick an easy distribution g (exponential, drawn as −μ·ln U) and a constant M so that M·g(s) is always above f(s).
  3. Draw s from g and U from Uniform(0,1). Keep s if U ≤ f(s) / (M·g(s)). Kept draws follow f exactly.
  4. Only 1 in M proposals is kept on average, so a tight envelope saves compute.

Why a PM cares: any fitted latency or cost curve becomes a simulator, so you can estimate P90s, savings and risk before a customer sees the change.

# Rejection sampler in Python
import numpy as np
rng = np.random.default_rng(102)
f = lambda s: 0.7*s*np.exp(-s/18)/18**2 + 0.3*s**3*np.exp(-s/30)/(6*30**4)
mu = 70.0
grid = np.linspace(0.01, 600, 6000)
M = 1.01 * np.max(f(grid) / (np.exp(-grid/mu)/mu))
s = rng.exponential(mu, 100_000)
keep = s[rng.uniform(size=s.size) <= f(s) / (M*np.exp(-s/mu)/mu)]
print(len(keep)/len(s), "≈", 1/M)
